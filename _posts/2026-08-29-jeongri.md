## 오늘 배운 것

 - 마크다운 문법
 - Git 과 GitHub 팀원 실습 
    * 기준 3개 → 일부러 어긴 PR → 반려 → 수정 → 승인
    * : 수업에서 올린 기능 기획서(feature-*.txt)들의 형식이 제각각(담당자 이름 누락, 한 줄짜리 설명 등)이라, 이대로 쌓이면 나중에 아무도 읽을 수 없다는 문제
    * 오늘 사용한 개념 : Pull Request, 코드 리뷰, 브랜치, 병합(merge)
    ---
    |항목|내용|
    |---|---|
    |브랜치|원본을 건드리지 않고 독립적으로 작업할 수 있는 작업 공간|
    |Pull Request|내 브랜치의 작업 내용을 원본에 합쳐달라고 요청하는 것|
    |코드리뷰|PR의 내용을 판정 가능한 기준으로 검토해 승인하거나 반려하는 과정|
    |병합(merge)|승인된 PR의 내용을 실제로 원본 브랜치에 합치는 작업
    ---

## 막혔던 것 

- 새 브랜치를 만들 때 어떤 브랜치를 기준으로 만들어야 하는지, 그리고 브랜치를 만든 후 실제로 그 브랜치로 전환이 잘 됐는지 헷갈리는 부분이 있었다.
